# Swarm State — WebGPU Render Path Hardening

## Objective
Root-cause WebGPU failures on strict adapters (12 uniform buffers/stage cap) so WebGPU can safely become the default again: no console errors, bloom/post-process works, table renders, clean PWA cache on renderer switch.

## Current Phase
**Iteration 1 complete — awaiting real strict-WebGPU hardware verify**

## Active Failure / Root Cause (resolved in code)
- **Root cause:** `DefaultRenderingPipeline` image-processing vertex stage binds ~17 uniform buffers; toggling features off does not shrink the layout. Strict adapters (cap 12) reject the pipeline and break rendering.
- **Fix:** Adapters below the DRP estimate use `MinimalBloomPipeline` — standalone `BloomEffect` (same bloom core DRP uses) without DRP/image-processing. WebGPU-first default restored with WebGL2 fallback only on init failure.

3. `npx vitest run` — 614 passed / 1 skipped / 0 failed
4. Playwright `?renderer=webgpu` load — no uniform-buffer validation errors (headless; falls back to WebGL2 if no GPU)

## What Changed This Iteration
- `src/effects/minimal-bloom-pipeline.ts` — bloom-only `PostProcessRenderPipeline` for strict WebGPU
- `src/effects/bloom-pipeline-types.ts` — shared `BloomPipelineController` interface
- `src/game/webgpu-post-process-profile.ts` — strict adapters → `bloom-only` tier (not `none`)
- `src/game/game-renderer.ts` — routes strict tier to `MinimalBloomPipeline`

## Blockers / Open Questions
- Headless CI Chrome reports pre-existing BJS uniform-buffer shader fallbacks on WebGL2 (14 shadow lights vs GL cap 14) — unrelated to WebGPU path; not a regression from this work.
- Full strict-WebGPU adapter validation needs Windows GPU or `maxUniformBuffersPerShaderStage=12` emulation in browser.

- If bloom-only still fails on some adapters, downgrade path remains (`none` tier + runtime guard).

## Emulating Strict Adapter (documented)
In browser after WebGPU boot: profile reads `engine.currentLimits.maxUniformBuffersPerShaderStage`. On Windows WebGPU defaults to 12. Force minimal path in dev by temporarily lowering `FULL_PIPELINE_UNIFORM_BUFFER_ESTIMATE` or mocking `readMaxUniformBuffersPerStage` to return 12.
