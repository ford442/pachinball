# #420 — C++ kinematic capture + cone/trap: port feeders off Rapier puppets

## Objective
Toys that hold a live ball (MagSpin, Gauss Cannon, Quantum Tunnel, NanoLoom, Prism Core, BallManager hologram catch, ball traps) must flip and steer the **C++ body the solver steps**, not a Rapier puppet or a TS per-step pin. Ball-trap funnels (Rapier cones) must collide in wasm-owner.
DoD (issue acceptance): PhysicsWorld.cpp < 500 after split with new TUs at -O0 in compile_commands.json; Catch2 for round-trip mass / no gravity / release velocity; `test:wasm-parity` covers the new mutators; MagSpin capture/release Playwright in wasm-owner with `lastRapierStepMs === 0`; trap funnel collides in wasm-owner; worker protocol parity updated and wasm-worker can capture.

## Current phase

## State at start (not what the issue text assumed)
#428 had already moved builders onto PhysicsApi / WasmTableWorld, so feeders were no longer writing to a Rapier corpse: `WasmBody` *emulated* kinematic by pinning the C++ (still dynamic) ball before every step with zero velocity. That emulation is what this lane replaces. The feeders' own well geometry is still outside the owner table scope (authored for the Rapier y = -0.9 surface) — unchanged here.

## Decisions
- **Cone: native, not a compound.** `native/src/Cone.cpp` (167 lines) does closed-form sphere-vs-cone in the (ρ, y) half-plane (base segment + slant segment, shallower exit when inside). It did not threaten the 500-line cap (it is its own TU), matches Rapier's `cone(halfHeight, radius)` exactly, and parity compares a slant hit against Rapier's own cone. Id family -9000.
- **setNextKinematicTransform dispatches on id sign**: < 0 mover (unchanged), ≥ 0 kinematic rigid body. One Embind/worker command, no parallel API.
- **Kinematic body semantics** (KinematicBody.cpp): → Kinematic zeroes inv mass/inertia and velocity, keeps pose; targets commit once per `step()` with velocity = pose delta / fixed dt (mover contract); a tick with no target leaves a driven body at rest; → Dynamic rebuilds mass/inertia from the stored mass+shape and keeps the last kinematic velocity. Kinematic bodies skip static solids + movers (no impulse possible; Rapier has no kinematic-vs-fixed contact) but still trip sensors.
- **WasmBody**: Rapier type (and disabled) → C++ body type via `engine.setBodyType`; `setNextKinematic*` → C++ targets (completing the missing half from the last target); `translation()` of a driven body reports its last target (worker snapshot trails a frame). `WasmTableWorld.beginStep()` / `pinForStep` deleted. Hinged flippers are never retyped.
- **CapturedBall driver** (`src/core/captured-ball.ts`): capture / steer / release used by all five feeders, BallManager, and traps. No `setBodyType(RigidBodyType.*)` left in `src/objects/feeders/*` or `object-ball-traps.ts`.
- **Traps now really hold**: catch → capture, drawn into the chamber, released after `trapHoldDuration` with the tuned boost, then `TRAP_REARM_SECONDS` (0.75 s) before they can catch again (a released ball starts inside the funnel). Before, "catch" only set velocity (0,-0.5,0) and the release path was dead code. Traps joined the owner table scope (GamePhysicsController).
