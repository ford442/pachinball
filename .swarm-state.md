## Things the brief got wrong or that you should know
- **Entry chunk grew by 0.01 KB** (209.07 -> 209.08 KB gzip), not zero: `WasmPhysicsEngine.getStateHash()` lives in `src/wasm/PhysicsModule.ts`, which is in the entry chunk, and the in-process (`wasm-owner`) path needs it. The worker protocol change itself is in the worker chunks.
- **WASM binary +18 KB** (173,389 -> 191,794 bytes) from canonical hashing + stateHash. My first cut was +89 KB (one `std::sort` instantiation per family inlined at -O3); it now uses one `qsort` and order-independent sums for kinematic targets.
- The version constant is in `src/wasm/wasm-types.ts` (`WASM_SNAPSHOT_VERSION`), not `snapshot-layout.ts`. The native status for an old blob is `SnapshotStatus::BadVersion`, not `VersionMismatch`. Test helpers (`fake-snapshot.ts`, two tests) hard-coded version 1; they now use the constant.
- **Not in the brief but needed:** the hash is now looser than the restore path assumed (it used to imply identical insertion order). Without more, restoring a blob into a world with the same statics added in another order would put group masks, mover poses and force-field vectors on the wrong items. The blob now writes that per-static runtime state in canonical rank order and `restore()` maps it back through the target's own ranking (Catch2 `a snapshot restores onto the right statics ...`). Items with byte-identical hashed content tie-break by insertion index, which is harmless unless their un-hashed runtime state differs (e.g. two same-size movers at different poses added in different orders).
- `stateHash` covers slightly more than the brief's list, using its own criterion ("affects the next step"): rotation, pending force, group masks and `active` per body, accumulator, world params, mover and force-field runtime state, pending kinematic targets. Contact manifold/buffers/transform buffer are out. Cost is O(bodies + static content) because it re-digests the table each call (including mesh triangles); it is not free per frame on a large adventure track.
- **UBSan: nothing halted.** The sanitizer suite is clean with fatal flags, so per the brief I added no `PinField`/`ForceField`/`BroadphaseGrid` fix. The #462 item 7 site is still real and latent: a throwaway test calling `setForceFieldEnabled(STATIC_HANDLE_OVERFLOW, true)` printed `ForceField.cpp:27:72: runtime error: signed integer overflow: -7000 - 2147483647` (probe reverted, not committed). Nothing in the suite reaches these lines, so fatal UBSan does not protect them yet; #462 items 7/9 should land with their Catch2 cases.
- **Gap against #459 acceptance A:** native-vs-WASM `getStateHash` equality is only checked ad hoc, because `scripts/run-wasm-parity.mjs` is outside the allowed files. The Catch2 fixture test now also writes `snapshot_parity.bin.statehash` next to the blob, so the follow-up is a two-line compare in that script.
- `docs/wasm-physics-engine.md` was not touched (`check:wasm-docs` passes), so it does not mention `getStateHash`, the canonical hash, or version 2.
- The original `staticHash` flake was intermittent (two earlier local runs passed), so 10/10 locally is evidence, not proof. The real gate is the Native Physics workflow on `main` three pushes in a row.
- Pre-existing, unrelated, same on `origin/main`: with Chromium forced onto software WebGPU (`--enable-unsafe-webgpu`), bootstrap fails with `TypeError: f.createDynamicTexture is not a function` from `createLCDGridTexture`. I did not touch it (rendering is out of bounds); it may only be a headless-adapter artefact, but it is worth a look on a real WebGPU device.
