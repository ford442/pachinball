## `wc -l native/src/PhysicsWorld.cpp`

**414** (was 688; limit 500). `Narrowphase.cpp` is 381 lines,
`KinematicMover.cpp` 216, `SensorVolume.cpp` 55, `BroadphaseGrid.cpp` 255 —
all well clear of the house 700-line limit.

Split rationale: `PhysicsWorld.cpp` kept everything that is genuinely
dispatch (ctor/dtor, transform buffer, body/hinge/mover/sensor CRUD,
`step()`/`substep()`'s pair-type routing, `setCollisionGroups`'s id-range
routing). Everything that is a geometric contact test + the sequential-
impulse solver (`applyContactImpulse` and all `resolveXxx` pair resolvers)
moved to `Narrowphase.cpp` — a single coherent concern, and the single
largest chunk of the original file. Movers and sensors got their *own*
translation units per the task's explicit file layout, not folded into
Narrowphase.cpp, since they carry state (`KinematicMover`) and a distinct
narrowphase (OBB vs sphere/capsule) the existing resolvers don't share.

### Playwright flake — proven pre-existing, not caused by this slice

`raise/lower launches a ball and skips Rapier step` asserts
`Math.abs(vz) > 0.5` after 90 fixed-dt `stepPhysics()` calls. Under repeated
runs it lands on one of two distinct outcomes: `vz > 0.5` (pass) or
`vz ≈ 0.227` (fail) — a real-time race between the `keyboard.down('Digit1')`
event and the flipper's hinge-motor state *before* the fixed-step loop
starts, not something the fixed-dt loop itself introduces.

To rule out a regression I ran the **unmodified base commit** (`git stash`,
rebuilt native+WASM, ran the same test 5×): **4/5 failed**, with the *exact
same* floating-point value (`0.2274113893508911`) as the failures seen on
this slice's code. This is a headless-Chromium/sandbox timing artifact
(likely the swiftshader/ANGLE software GL path combined with this
container's scheduling) that predates and is independent of this change.
`engine: 'wasm-owner'` and `rapierMs: 0` were asserted true in every run,
pass or fail — WASM was genuinely active throughout, never a silent
`[Bootstrap][physics-degrade]` fallback. The other two flipper-spec tests
(`plunger leaves the launch lane`, `bumper contact awards score`) were green
on every run.

Browser note: this container's preinstalled Chromium (`chromium-1194`) is
older than what this Playwright version (1.57.0) expects
(`chromium_headless_shell-1200`), so `browserType.launch` fails outright
without an override. I ran with `playwright.config.ts`'s `launchOptions.
executablePath` temporarily pointed at `/opt/pw-browsers/chromium` (per the
`run` skill's guidance) for verification, then **reverted that config edit**
— it is not part of this slice's diff.
