### Upstream changelog facts for a future 0.2x migration (verified from the dimforge changelogs)

- rapier.js **0.19.0** (Rapier core 0.29): removed the legacy PGS API: `World.numAdditionalFrictionIterations`,
  `switchToStandardPgsSolver`, `switchToSmallStepsPgsSolver*`. This is what removes the property our OP-1
  tuning sets. Core 0.29 also removed `IntegrationParameters::pgs_legacy` / `tgs_soft_without_warmstart`.
- Core **0.18.0** (Jan 2024, rapier.js ~0.12-0.13) introduced the TGS-soft solver: iteration count is
  `numSolverIterations`; `switch_to_standard_pgs_solver()` was the way back to the old one.
- Core **0.31.0**: `contact_natural_frequency` / `contact_damping_ratio` grouped into
  `IntegrationParameters::contact_softness`; erp/cfm moved onto `softness` fields; per-joint softness.
- Core **0.35.0-beta.0**: contact defaults changed (`normalized_prediction_distance` 0.002 -> 0.02,
  `normalized_max_corrective_velocity` 10 -> 3, `normalized_allowed_linear_error` 0.001 -> 0.005, stiffer
  `static_contact_softness`); `RigidBody::additional_solver_iterations` now adds whole solver substeps.
- Not verified: the exact rapier.js release that carries each core version for 0.20 / 0.21 (rapier.js's own
  changelog stops at 0.19.3). The measured effect of 0.21 on this repo (from #583): its lazy chunk doubles
  (1.6 MB gzip vs the 800 KB budget), `dist/` exceeds the 40 MiB cap, and its typings need
  `lib: ESNext.Disposable`.
