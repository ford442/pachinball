## The two historical browser failures

### display-states: IDLE -> JACKPOT

The spec emits `display:set = jackpot` in one page evaluation and reads the state in a
later evaluation (`tests/display-states.spec.ts:141-160`). It never starts a jackpot
effect. The display event handler synchronously calls `setDisplayState`
(`src/display/display-core.ts:470-478`), but
`finishJackpotIfDone` (`src/game/physics/step-gameplay.ts:29-35`) emits `display:set = idle`
whenever the display says JACKPOT and `effects.isJackpotActive` is false.
`src/game/physics/sim-phase.ts:35` invokes this cleanup on simulation updates.

Thus a simulation update between the two evaluations can reset the artificial jackpot;
this is not evidence of Rapier gameplay drift. A follow-up should test a real jackpot
lifecycle or isolate synchronous display dispatch from simulation cleanup, not add a
timeout or relax the expected state. No browser assertion was weakened here.

### render-hygiene: frozen decor empty

This was not reproduced in the restricted environment and is **not claimed solved**.
The exact retained checks are `tests/render-hygiene.spec.ts:391-426`: the allowlist must
contain twelve named unlit materials and the scene's frozen set must equal it.

Source evidence narrows the next probe:

- `src/game.ts:206-211` creates the room before system initialization.
- `src/game/game-renderer.ts:244-260` collects explicit unlit material candidates.
- `src/game/game-renderer.ts:175-185` passes the candidate list to installation.
- `src/game/init/register-static-scene.ts:25-34` obtains the renderer's candidates.
- `src/game/static-scene-install.ts:54-56` copies those candidates into the frozen set.
- `src/game/frozen-material-set.ts:96-103` freezes every retained member on refreeze.
- The gate can delay refreeze for holds, changing watched state or readiness; a bounded
  wait alone does not distinguish an empty allowlist from a nonempty but thawed set.

The existing gate/install/material tests pass (41 assertions/tests reported by Vitest),

than treating these unit tests as an E2E substitute.
